# Pulse — Design Spec
_Date: 2026-08-26_
_Status: Approved_

---

## 1. Overview

Pulse is a personal nutrition, health and fitness Progressive Web App. It combines simplified Strava-style activity tracking (via Garmin Connect API) with simplified MyFitnessPal-style nutrition logging, presented in a single today-focused dashboard.

Primary user: David McGuinness. Architecture is designed to support multi-user in a future phase without a rewrite.

The name "Pulse" plays on two meanings: the body's heartbeat/pulse, and pulses the food group — reflected in the logo concept.

| PWA | next-pwa | Service worker + manifest with minimal config |
| Testing | Vitest | Fast, native TypeScript |
| Validation | Zod | API boundaries, AI response validation |

## 4. Data Model

### users
```sql
id, clerk_id, email, created_at
height_cm, weight_kg, age, sex, activity_level
-- goal columns (all 17 nutrients)
calorie_goal, protein_g, carbs_g, fat_g, fibre_g, sugar_g,
sat_fat_g, poly_fat_g, mono_fat_g, trans_fat_g, cholesterol_mg,
sodium_mg, potassium_mg, calcium_mg, iron_mg,
vitamin_a_pct, vitamin_c_pct
```

### foods
```sql
id, name, brand, barcode
-- per-serving nutrition (all 17 nutrients)
calories, protein_g, carbs_g, fat_g, fibre_g, sugar_g,
sat_fat_g, poly_fat_g, mono_fat_g, trans_fat_g, cholesterol_mg,
sodium_mg, potassium_mg, calcium_mg, iron_mg,
vitamin_a_pct, vitamin_c_pct
-- serving
serving_unit         -- enum: g | ml | item
serving_description  -- nullable, e.g. "1 falafel"
serving_size_g       -- always grams equivalent for nutrient maths
-- provenance
source               -- enum: open_food_facts | manual | ai_scan
verified_by_user     -- bool; false until user reviews/enriches
```

Items logged by unit (e.g. "2 falafels") are converted to grams at log time using `serving_size_g`. All nutrient calculations use grams internally.

### nutrition_log
```sql
id, user_id, food_id, logged_at (date), quantity_g
-- nutrient snapshot at log time (all 17 nutrients)
calories, protein_g, ...
```

Nutrients are snapshotted at log time so editing a food record does not corrupt history.

### garmin_activities
```sql
id, user_id, garmin_activity_id (unique)
type  -- enum: run | walk | cycle | swim | strength | other
started_at, duration_s, distance_m
avg_pace_s_per_km, avg_hr, max_hr, calories_burned
vo2_max
raw_json  -- full Garmin payload; future-proofs against API changes
```

### garmin_daily_wellness
```sql
id, user_id, date (unique per user)
steps, resting_hr
body_battery_high, body_battery_low
hrv_rmssd
sleep_score, sleep_duration_s
sleep_deep_s, sleep_light_s, sleep_rem_s, sleep_awake_s
calories_burned
```

### garmin_tokens
```sql
user_id (FK), access_token (encrypted), refresh_token (encrypted)
expires_at, webhook_verification_key
```

Tokens encrypted at rest with AES-256; key stored in environment variable.

### daily_insights (M4)
```sql
id, user_id, date (unique per user), insight_text, generated_at
```

## 6. Pages & Navigation

Bottom nav (PWA, thumb-friendly): **Today | Log Food | Activity | Trends | Profile**

### Today (home)
- Hero cards: Body Battery (current / high / low), Sleep Score + stage breakdown (deep / REM / light / awake)
- Calorie ring: consumed / goal / burned (net)
- Macro progress bars (protein, carbs, fat, fibre) — colour-coded
- Steps progress toward daily goal
- Recent food log entries (today) with quick-delete
- Tap any card → detail view
- AI insight card (M4) — generated once daily, streamed

### Log Food
- Barcode scan (camera) → Open Food Facts lookup → quantity picker → log
- Text search → same flow
- Recent foods (last 7 days, most frequent first)
- Photo scan of nutritional label → pre-filled form (M4)
- New food form — manually create or edit an AI/OFf-seeded entry

### Activity
- Recent activities list (type / distance / pace / duration)
- Daily wellness summary: HRV, resting HR, VO2 max
- Garmin sync status + last synced timestamp

### Trends
- 7 / 30 / 90 day selector
- Charts: calories in vs burned, macro breakdown, steps, sleep score, body battery, HRV
- Line and bar charts — no overbuilt dashboard

### Profile
- Personal stats: height, weight, age, sex, activity level
- TDEE calculator → sets all nutrient goals
- Per-nutrient goal manual overrides
- Garmin Connect OAuth connection status + disconnect

## 7. Garmin Integration

**Flow:**
1. User taps "Connect Garmin" in Profile → OAuth 2.0 redirect to Garmin Connect
2. Callback at `/api/garmin/callback` stores encrypted tokens
3. Garmin pushes data to `/api/garmin/webhook` after each device sync
4. Webhook handler verifies Garmin signature, upserts into `garmin_activities` and `garmin_daily_wellness`
5. Token refresh handled transparently on each API call

**Data received via webhook:**
- Activity summaries (all activity types)
- Daily summaries (steps, calories, body battery, resting HR)
- Sleep summaries (score + stages)
- Health snapshot (HRV, VO2 max)

**Note:** Garmin developer API credentials require registration at developer.garmin.com. Approval can take several days — register before starting M1 Garmin work.

## 8. PWA

- `manifest.json`: app name, icons, `display: standalone`, theme colour from logo palette
- Service worker via `next-pwa`: caches shell + static assets; today dashboard readable offline
- Offline nutrition log: entries queued in IndexedDB, synced on reconnect
- Barcode scanner: native `getUserMedia` camera API — no native wrapper needed on Android Chrome
- Install prompt: handled natively by Chrome on Android (Pixel 10 Pro XL)

## 9. AI Features (Milestone 4)

### 9.1 Label Vision Pipeline

`POST /api/food/scan-label`

1. User photographs nutritional label
2. Image sent to Claude Haiku with structured prompt
3. Response validated against Zod schema matching `foods` structure — hallucinated fields rejected
4. Pre-fills new food form; user reviews and saves
5. Saved with `source: ai_scan`, `verified_by_user: false`

Demonstrates: structured LLM output pipeline, Zod validation of AI responses, vision model usage.

### 9.2 Nutrition Intelligence Agent

`POST /api/ai/daily-insight`

Claude Haiku with tool use. Three tools:
- `get_nutrition_today` — today's logged nutrients vs goals
- `get_wellness_today` — Garmin daily wellness data
- `get_7day_averages` — rolling averages for context

Agent reasons across all three data sources and returns 2–3 sentence insight. Streamed to the UI. Cached in `daily_insights` — does not re-run on page refresh.

Example output: _"Your HRV is 15% below your 7-day average. You hit your protein target but reached only 60% of your iron goal — on your lower-HRV days, iron intake has consistently been below 70%."_

Cost: ~$0.01–0.03/day with Haiku.

Demonstrates: agentic tool use, multi-source reasoning, streaming UI, result caching.

## 10. Security

- Garmin tokens encrypted at rest (AES-256, key in env var)
- Webhook signature verification on every Garmin push
- All API routes behind Clerk auth middleware — no route accidentally public
- No API keys in client bundle (server-side only)
- Zod validation at all API boundaries

---

## 11. Testing

- Vitest unit tests covering: TDEE calculator, nutrient snapshot logic, Garmin webhook parser, Zod schema validation
- Error boundaries on dashboard cards — one failed fetch does not blank the whole page
